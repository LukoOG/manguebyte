# Technical debt

An audit of what the code owes, so that shortcuts are chosen on purpose and
paid back in order. Update it when an item is fixed or a new one is taken on.

Last audit: 2026-10-15, covering every crate in the workspace.

## Scoring

Each item is scored from 1 to 5 on three axes:

- **Impact**: how much it slows down people using or extending the framework.
- **Risk**: how bad it is if it is never fixed.
- **Effort**: how hard the fix is.

`Priority = (Impact + Risk) × (6 − Effort)`. Higher goes first.

## Paid back in this audit

| Item | What was done |
|---|---|
| A plugin could not say which MIDI controllers it listens to, so every VST 3 instrument exposed 2,080 hidden controller parameters, which REAPER 7.82 lists in its generic view (items 25 and 41) | `Plugin::MIDI_CONTROLLERS` declares them as a `MidiControllers` set built in a const (`NONE`, `MUSICAL`, `ALL`, `with`, `without`, `per_channel`); the VST 3 wrapper exposes one hidden parameter per declared controller, shared by every channel, and delivers each move on all 16 channels so that `Synth` hears it on any channel (see item 54). Mangue Pluck shows a host 6 + 13 parameters instead of 2,086, which the parameter scan of Steinberg's validator confirms, and passes 537 of 537 tests in its extensive mode. `manguebyte-host`'s VST 3 tests check the 19 parameters, that every channel maps to the same ones, and that a wheel and a pedal on channel 1 bend and hold a note on channel 6 exactly as that channel's own would |
| Two offline renders of the same project in REAPER differed by one unit in the last place once many voices of `plugins/pluck` overlapped (item 42) | The cause was in `Synth`: `reset` kept the clock of voice ages, and a free voice was chosen as the oldest, so after a reset or a reactivation the same note fell on another voice and the voices were summed in another order. A free voice is now chosen by position, `reset` clears the ages, the notes and the pedal, and Mangue Pluck follows its reverb and level events on their exact frames and starts each from its value after `prepare` or `reset`. Reproduced and tested through `Harness` and the CLAP entry point in process (37 notes at full velocity, every parameter at its extreme); not yet confirmed in REAPER (item 56) |
| Mangue Pluck's output went far past full scale with every parameter at its maximum, and it was said to be a Karplus-Strong synth a few cents flat (item 43, partly) | Pluck never had a Karplus-Strong delay: it is a sawtooth through a state-variable filter, and the drift was the filter's phase lag growing as it closed (up to -3 cents at the defaults, -7.5 with Q 8). `StateVariableFilter::phase_response` lets the voice advance its oscillator by the lag the filter gained, so the measured keys stay within 0.15 cent at the settings `tests/tuning.rs` covers. The output is kept in range by a resonance compensation, a trim of the reverb's wet sound, a share of the headroom per voice, a soft knee from -3 dBFS and a limiter at -1 dBFS with no latency, and nothing comes out flat at the ceiling. The default level is now -4 dB, chosen so that a chord around middle C at the default settings peaks at about -6 dBFS. The tuning of a resonant sweep across a low note's fundamental is still open (item 43) |
| No `.lv2` bundle could be built (item 45) | `cargo mangue bundle --format lv2` writes `<Name>.lv2` with the library and the Turtle files of `manguebyte_lv2::bundle_files`, which a small program it builds against the plugin's crate writes through a function `export_lv2!` defines; `install` and `uninstall` know LV2's folders. The facade has an `lv2` feature, both example plugins call `export_lv2!`, the command's end-to-end test bundles a generated plugin as LV2 on three systems, and a CI job bundles both examples and loads them with lilv |
| The VST 3 wrapper never called `OpenEditor::set_visible`, so a `manguebyte-gui` editor ran frames from the moment it opened, under CLAP too, before the host's `show` (item 47) | The VST 3 view calls `set_visible(true)` once `attached` has succeeded and `set_visible(false)` at the start of `removed`, and `manguebyte-gui` opens an editor hidden, with no frame timer, until it is shown. `before_show_the_editor_is_not_shown_and_runs_no_frames` runs again, and new tests check the VST 3 side |
| After a panic in the plugin, the CLAP and VST 3 wrappers did not give it the values the host had sent in that block, so a plugin that follows events alone kept the old ones (item 53) | Both now do what the LV2 wrapper does: the next block starts with every parameter's value. Each has a regression test, seen to fail with the fix taken out |
| The VST 3 wrapper did not send parameter changes back to the host (item 23) | The `IComponentHandler` the host gives is kept and released correctly, and editor gestures reach it as `beginEdit`, `performEdit` with the value the control set, and `endEdit`, on the main thread. Nothing infers an edit by comparing values. Tested with fake COM objects in every order |
| An edit stored by the interface while a block was being prepared could be undone by the block, in the CLAP and VST 3 wrappers and in the standalone engine | `ParamWatcher::apply_and_remember` stores only the events that did not come from the watcher and records what each parameter holds without reading it back (`Param::stored_plain`). Each place has a test that fails on the old code |
| WAV, AIFF and FLAC were read whole into memory (item 7) | `AudioReader` and `AudioWriter` work block by block with exact seeking and bounded memory, and `StreamingPlayer` and `RecordingWriter` bridge them to an audio callback without waiting. Tested bit-exact against the whole-file readers over 51 files, hundreds of block patterns and seeks |
| `Gain` was not bit-exact across block sizes while gliding, which contradicted the block-size claim | `Smoothed::skip` steps exactly as `next_value` does, and a repeated target no longer restarts the glide. Found by an engineer reviewing the new effects |

| Both validators ran against one example plugin, an instrument with no audio input | `plugins/duck`, an effect with a main input, a sidechain and a bypass switch, goes through both validators in CI beside the instrument. `Harness::process_with_sidechain` lets its tests feed both inputs |

## Remediation plan

Small items are done alongside feature work in the area they touch. The
order below is for the ones that need their own change.

**Next (before any plugin work)**

1. Output events in `ProcessContext`, for processors that emit notes, and
   non-parameter plugin state (samples, wavetables) through the swap pattern.
2. Item 5: security advisories in the `cargo deny` job.
3. Item 12: a first release to crates.io, which needs the owner's account.
4. Item 3: extend the allocation guard to `devices` and `params`.

**Soon (during the rest of Phase 1)**

5. Item 6: maths on `Sample`, done together with the filters that need it.
6. Items 26 and 27: the plugin API changes that let a plugin say what it does.
7. Item 11: timing information in device callbacks.
8. Item 2 and item 4: fuzz targets and benchmarks.
9. Item 14: `EnumParam` that saves a stable name per variant.

**Later**

10. Item 9: `no_std` for `core` and `dsp`.
11. Item 8: drift correction, once a resampler exists.
12. Item 10: faster FFT kernels behind the same API.
13. Item 13: a self-hosted runner with a loopback device.
