# Technical debt

An audit of what the code owes, so that shortcuts are chosen on purpose and
paid back in order. Update it when an item is fixed or a new one is taken on.

Last audit: 2026-10-13, covering every crate in the workspace.

## Scoring

Each item is scored from 1 to 5 on three axes:

- **Impact**: how much it slows down people using or extending the framework.
- **Risk**: how bad it is if it is never fixed.
- **Effort**: how hard the fix is.

`Priority = (Impact + Risk) × (6 − Effort)`. Higher goes first.

## Paid back in this audit

| Item | What was done |
|---|---|
| There was no VST 3 support | `manguebyte-vst3` wraps the same `Plugin`. It is checked three ways: a test host that drives it through COM under the allocation guard, Miri, and Steinberg's validator in CI on three systems. The test host found that a change delivered in a block with no audio never reached a plugin that follows events, and that `Synth` forgot the pitch wheel between notes; the validator's report showed that the class id had the same bytes on every system, where VST 3 needs the same numbers |
| The CLAP wrapper's `process` was not under the allocation guard | `crates/manguebyte-clap/tests/abi.rs` counts heap calls made inside `process` across the C boundary and requires zero, for automation, notes, reported changes and the block after a state restore |
| The CLAP wrapper was only checked by tests written by the same hand | CI builds the example plugin and runs the CLAP project's own `clap-validator` against it. Its first run found two defects the in-house tests had missed: a value just below zero displayed as `-0.0`, which read back as a different text, and restored state was not announced to the host with a rescan request. Both are fixed and have regression tests |
| `Processor::process` took only a buffer, with no way to express events, automation or transport | `process_with` takes a `ProcessContext` carrying one timestamped `EventBuffer`, the `Transport` and a sidechain. `AudioBuffer::windowed` and `split_at_events` apply each event on its frame with no copying. See ADR 0005 |
| Nothing checked that output is independent of block size | `crates/manguebyte/tests/offline.rs` renders a song with six different block patterns and requires bit-identical results. It caught a real defect on its first run: finished voices kept advancing until the end of their block |
| Real-time safety rested on doc comments alone | `crates/manguebyte-dsp/tests/realtime.rs` installs a counting allocator and fails if any processor or transform allocates, reallocates or frees while processing |
| The wait-free queue's `unsafe` code was only tested natively | CI runs `manguebyte-core` under Miri, which detects undefined behaviour and data races |
| A build without the audio backend was never exercised | CI builds and tests the facade with `--no-default-features` |
| `ParamSmoother` in `f32` stalled short of its target on long exponential ramps and never reported finishing | State is kept in `f64`; a regression test covers a two-second ramp at 96 kHz |
| Device code duplicated an eleven-arm match per stream direction | One `with_sample_type!` macro shared by output, input and duplex |

## Remediation plan

Small items are done alongside feature work in the area they touch. The
order below is for the ones that need their own change.

**Next (before any plugin work)**

1. Output events in `ProcessContext`, for processors that emit notes, and
   non-parameter plugin state (samples, wavetables) through the swap pattern.
2. Item 5: `cargo deny` in CI.
3. Item 12: a first release to crates.io, which needs the owner's account.
4. Item 3: extend the allocation guard to `devices` and `params`.

**Soon (during the rest of Phase 1)**

5. Item 6: maths on `Sample`, done together with the filters that need it.
6. Item 7: streaming readers and writers, done with the second file format.
7. Item 11: timing information in device callbacks.
8. Item 2 and item 4: fuzz targets and benchmarks.
9. Item 14: `EnumParam` that saves a stable name per variant.

**Later**

10. Item 9: `no_std` for `core` and `dsp`.
11. Item 8: drift correction, once a resampler exists.
12. Item 10: faster FFT kernels behind the same API.
13. Item 13: a self-hosted runner with a loopback device.
